# Design decisions

- **PostgreSQL/Prisma:** relational history, foreign keys, project-row locking and indexed ordered events. Migrations are additive SQL; existing projects remain compatible.
- **BullMQ:** persistent background delivery and stalled-job handling. A small reconciler bridges the database/queue dual-write gap. Reconciliation errors are isolated by item.
- **Host worker:** safe Docker CLI arguments avoid mounting a Docker socket into application services. The operator/host remain trusted. Builds are not a secure untrusted-code sandbox.
- **Built-in application gateway:** Node HTTP forwarding gives stable local hostnames without adding a mandatory Caddy/Traefik container or requiring host DNS configuration in Chromium. It routes only application hostnames, supports streaming/upgrades, and queries the current pointer directly to avoid stale route promotion caches.
- **cloudflared quick tunnels:** opt-in sharing without an account or subscription. URLs are temporary, require outbound DNS/connectivity, and only appear after a real connected tunnel. Stable named public domains and remote dashboard access are deferred.
- **Write-only encrypted variables:** no reveal endpoint, plaintext CLI arguments or plaintext database snapshots. One backed-up host key is simpler for a trusted single operator; rotation/managed secret stores are deferred. Docker's host operator can still inspect container environment values.
- **Image-based rollback:** reuse already-built owned images with original variable snapshots; require readiness and create a new historical attempt. Keep current traffic until promotion. No database or persistent-volume rollback is attempted.
- **Background health checks:** health survives closed browser tabs; Docker process status alone does not imply HTTP readiness. Bounded request deadlines, four checks at a time and an independent heartbeat keep monitoring predictable.
- **Frontend:** service-oriented navigation and denser workspace tables, graphite surfaces, restrained violet/green accents, native confirmation dialogs, actual charts and useful empty/error states. The layout is inspired by infrastructure platforms without copying their branding.
- **Isolated testing:** temporary databases/queues and an explicitly guarded local Git clone boundary allow real end-to-end Docker tests without publishing test repositories or adding a local-path API. Public tunnel verification is separate and never simulated.
